## Secuencia de API

1. `register_transfer(candidate_dir, inp_path, domain_policy, planned_runs, volume_bands_m3, output_root)` recibe solo planes: cada registro contiene `network_id`, `run_id`, `event_series_components`, `event_series_sha256`, `hydraulic_policy` y `hydraulic_policy_sha256`. Se escribe `registration.json` y su hash. No se suministran resultados ni etiquetas. Los componentes deben cumplir el mismo JSON canónico/hash usado por la procedencia del proyecto.
2. Después de simular bajo el plan y cerrar QA, `predict_transfer(directory, keys, features, runs)` recibe claves de `KEY_COLUMNS`, features en el orden del contrato y registros de corrida con identidad, hash de evento y decisión de calidad. Vuelve a calcular la decisión hidráulica y verifica política, INP, par y registro. Escribe `rejections.json` con las corridas no elegibles y sus motivos, y excluye sus filas de la predicci?n y los puntajes. Un fallo de dominio de red o la ausencia de corridas elegibles impide puntuar; se inicia un experimento nuevo al corregir entradas. Si hay corridas elegibles, escribe `inputs.csv`, `predictions.csv` y `prediction_seal.json`, que cubre las entradas, predicciones y el informe de exclusiones. La API de predicción no recibe etiquetas.
3. Solo después, `score_transfer(directory, labels)` verifica el hash sellado, une por red/corrida/nodo, comprueba unicidad, cobertura, finitud, volúmenes no negativos y consistencia con el umbral. Escribe `scores.json` una única vez con hash de etiquetas, RMSE, MAE, sesgo, matriz de confusión, recall, PR-AUC cuando aplica, falsos negativos por banda y desglose por forma. La forma del hidrograma es un estrato descriptivo, no un holdout de familia física.

**Pendientes para uso real:** vincular el hash de cada evento y sus componentes a los archivos efectivos utilizados por SWMM; vincular las features y etiquetas a la misma corrida, reporte de inundación y dataset verificados; documentar el criterio de ingeniería de admisión de B y revisar manualmente las decisiones de calidad. La API verifica que los hashes declarados son consistentes, pero no verifica aún esos archivos de eventos ni prueba que las tablas suministradas provienen del reporte de la corrida. Las copias de sello y archivo en una misma carpeta detectan cambios accidentales cuando se conserva el sello, no ofrecen una firma criptográfica independiente. Ninguno de esos requisitos se resuelve con esta prueba sintética.

Las políticas de continuidad y drenaje actuales son provisionales. El resultado por dos redes no estima el desempeño sobre una población de redes futuras. Este flujo no entrena modelos, no selecciona modelos usando B y no los promueve.
